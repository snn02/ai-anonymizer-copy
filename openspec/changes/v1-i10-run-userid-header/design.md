## Context

По текущей диагностике `doctor` проходит (200), а `run` получает `401` на `POST /v1/tasks/file_anonymization` при том же `Authorization` и `partner-id`. Актуальная документация метода указывает заголовок `user-id`; сейчас в runtime `run` он не отправляется.

## Goals / Non-Goals

**Goals:**
- Добавить поддержку заголовка `user-id` в `run` для `POST /v1/tasks/file_anonymization`.
- Зафиксировать единое поведение источника `user-id` (`config/env`) и критерии валидации UUID.
- Подтвердить поведение тестами и синхронизировать документацию.

**Non-Goals:**
- Изменение модели auth (`mode=prod|mvp`) и механизма секретов.
- Изменение `doctor`-контракта `anonymization_fields`.
- Поддержка новых параметров `tags`/`tags-numeration` в `run` в этом change.

## Decisions

1. `run` отправляет `user-id`, если параметр задан.
- Решение: читать `api.user_id` из текущей конфигурации и добавлять header `user-id` в `POST /v1/tasks/file_anonymization`.
- Почему: соответствует API-доке и устраняет расхождение между `doctor` и `run`.
- Альтернатива: всегда отправлять фиксированный UUID fallback; отклонено как неявное поведение и риск конфликтов.

2. Валидация `user-id` остается централизованной в preflight.
- Решение: использовать существующую проверку UUID в preflight/runtime и не дублировать отдельную валидацию в API client.
- Почему: меньше дублирования и единая точка политики.
- Альтернатива: локальная валидация в `run`; отклонено.

3. Совместимость при отсутствии `user-id`.
- Решение: если `api.user_id` пуст, header не отправляется (backward-compatible поведение).
- Почему: снижает риск регрессий в контурах, где header опционален.
- Альтернатива: сделать header обязательным сразу; отклонено до подтверждения от API-владельца.

## Risks / Trade-offs

- [Risk] API на части контуров может требовать `user-id` как обязательный → Mitigation: явный тест/док-правило и диагностика ошибки при 401.
- [Risk] Некорректный UUID в `api.user_id` приведет к preflight-block → Mitigation: оставить явное сообщение валидации и пример валидного формата в docs.
- [Risk] Возможный дрейф между OpenAPI и runtime на `tags/tags-numeration` → Mitigation: зафиксировать как out-of-scope и вынести отдельным change при необходимости.
