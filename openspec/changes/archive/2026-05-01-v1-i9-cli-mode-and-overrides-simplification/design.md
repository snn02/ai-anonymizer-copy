## Context

Текущий CLI в `v1` содержит избыточное число override-флагов, что приводит к ошибкам запуска и рассинхрону между командами (`doctor/scan/list/run`). Пользовательский сценарий MVP требует предсказуемого режима: минимум флагов в CLI, остальные параметры из `config/env`, и единый выбор режима через один параметр.

## Goals / Non-Goals

**Goals:**
- Ввести единый переключатель режима `mode=prod|mvp`.
- Сократить набор CLI override до `--config`, `--mode`, `--workspace-path`, `--output-path`.
- Перенести все остальные runtime-параметры в `config/env`.
- Для `mvp` разрешить работу с production API при явном режиме и предупреждении.

**Non-Goals:**
- Изменение API-контрактов внешнего сервиса.
- Отмена OS Secret Store в режиме `prod`.
- Упрощение структуры security/boundary проверок.

## Decisions

1. Единый режим через `mode`.
- Решение: заменить двойную механику (`runtime_profile` + `insecure_no_secrets`) единым `mode`.
- Почему: меньше комбинаций состояний и ошибок конфигурации.
- Альтернатива: оставить оба флага; отклонено как UX-сложно и дорого в поддержке.

2. Минимальные CLI override.
- Решение: оставить только четыре override-точки (`config`, `mode`, `workspace_path`, `output_path`) для всех команд.
- Почему: ускоряет запуск, уменьшает дублирование и риск рассинхрона.
- Альтернатива: частично оставить текущие флаги; отклонено, так как не решает корневую перегрузку.

3. Секреты в `mvp` только из config/env.
- Решение: убрать CLI-передачу `audit_hmac_secret`; для `mvp` использовать `config/env`.
- Почему: ниже риск утечки секрета в shell history.
- Альтернатива: оставить CLI override секретов; отклонено по операционным рискам.

4. Разрешить `mvp` на production API.
- Решение: снять блокировку `mvp` для production host, оставить явное предупреждение и режимный контроль.
- Почему: это требование эксплуатации текущего MVP.
- Альтернатива: запрет на production для `mvp`; отклонено как несовместимое с реальным процессом пользователей.

## Risks / Trade-offs

- [Risk] Ошибка из-за устаревших скриптов с удаленными флагами → Mitigation: явные ошибки неизвестных флагов + migration notes в user-guide.
- [Risk] Ослабление security-позиции при `mvp` в production → Mitigation: сохранить явное предупреждение, логирование режима, документировать short-lived токены.
- [Risk] Регрессии в командах при удалении флагов → Mitigation: интеграционные тесты для `doctor/scan/list/run` и p0-сценарии в `docs/test-scenarios.md`.
