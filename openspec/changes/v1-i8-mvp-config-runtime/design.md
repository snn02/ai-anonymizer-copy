## Context

В `v1-1-ws` профиль и секреты для MVP должны работать в изолированной AI IDE без OS Secret Store. На практике пользователь задает `runtime_profile`, `insecure_no_secrets`, `api.auth_token`, `audit.hmac_secret` в `config`, но `run` может уходить в ветку keyring и падать с `secret not found`.

## Goals / Non-Goals

**Goals:**
- Зафиксировать единое поведение `doctor` и `run` для профиля `v1-1-ws`.
- Гарантировать, что при `v1-1-ws` + `insecure_no_secrets=true` чтение идет из config/env/CLI без обращения к OS Secret Store.
- Уточнить и протестировать приоритет источников: `CLI > env > config > default`.
- Синхронизировать пользовательскую и техническую документацию с фактическим поведением.

**Non-Goals:**
- Изменение контракта команды `run` в standard `v1`.
- Переработка OS Secret Store интеграции.
- Добавление новых API-методов.

## Decisions

1. Единый runtime-гейт для MVP.
- Решение: использовать одинаковую проверку в `doctor` и `run`: если `runtime_profile=v1-1-ws`, то обязательны `insecure_no_secrets=true`, `api.auth_token`, `audit.hmac_secret`.
- Почему: исключает расхождение поведения между командами.
- Альтернатива: оставить разные ветки логики в `doctor` и `run`; отклонено из-за повторяемых инцидентов и сложности поддержки.

2. Явный приоритет источников параметров.
- Решение: документировать и покрыть тестами фактический приоритет `CLI > env > config > default` для MVP-параметров.
- Почему: устраняет неоднозначность для операторов и ускоряет диагностику.
- Альтернатива: только документация без тестов; отклонено, т.к. высокий риск регрессии.

3. Документация как часть acceptance.
- Решение: изменения считаются завершенными только при синхронизации `user-guide`, `technical/configuration`, `v1 plan`, `test-scenarios`, `action-log`.
- Почему: правила проекта требуют отсутствия рассинхрона.
- Альтернатива: постфактум обновление документации; отклонено.

## Risks / Trade-offs

- [Risk] Пользователь запускает `run` без `--config` и без env, ожидая чтение из файла по умолчанию → Mitigation: добавить явные примеры запуска и `doctor` pre-check в user-guide.
- [Risk] Сохранение токенов в config увеличивает операционный риск утечки → Mitigation: оставить это только для `v1-1-ws`, явно пометить non-production и короткий TTL токена.
- [Risk] Изменения в parser/loader могут повлиять на standard `v1` → Mitigation: отдельные тесты на invariant `v1` (только OS Secret Store).
