# test-scenarios

## Правило маркировки

Каждый сценарий тестирования помечается применимостью: `[v1]`, `[v2]`, `[v1+v2]`.

## Приоритеты и release gate

- `p0` — критично для безопасности и корректности; обязательно pass для релиза версии.
- `p1` — важно для надежности и UX; желательно pass, допускается временный known issue только по согласованию.
- `p2` — улучшения/операционные проверки; могут идти после релиза как запланированный follow-up.

Правило релиза `v1`:
- все сценарии `p0` с меткой `[v1]` или `[v1+v2]` должны быть в статусе pass.

## Сценарии тестирования

### [v1] [p0] T1: первичная настройка и preflight

1. Задать `raw_path` и `output_path`.
2. Выполнить `anonym doctor`.

Проверки:
- CLI валидирует конфигурацию;
- CLI проверяет доступность API и наличие секретов;
- CLI блокирует небезопасные конфигурации boundary/ACL;
- ошибки возвращаются в понятном виде.

### [v1+v2] [p0] T2: базовый пользовательский поток

1. Выполнить `anonym scan`.
2. Выполнить `anonym list`.
3. Выполнить `anonym run <id>`.

Проверки:
- анонимизированный файл создается в `output_path`;
- имя результата не раскрывает исходное имя/PII;
- исходный файл в `raw_path` не изменяется;
- статус выполнения отражается в очереди.

### [v1] [p0] T3: path hardening

1. Выполнить `anonym run <relative_path>` и негативные кейсы обхода.

Проверки:
- поиск ограничен только `raw_path`;
- блокируются `..` path traversal-паттерны;
- блокируются symlink/reparse points;
- блокируются UNC/ADS кейсы вне политики;
- обрабатываются только файлы, не директории.

### [v1+v2] [p1] T4: запуск по примерному имени

1. Выполнить `anonym run invoice april`.

Проверки:
- одно совпадение запускается автоматически;
- при нескольких совпадениях выводится список кандидатов с `id` и требуется явный выбор;
- при нуле совпадений выводятся похожие варианты.

### [v1] [p0] T5: лимиты и устойчивость

Проверки:
- работают ограничения `max_file_size` и timeout;
- при превышении лимитов возвращается понятная ошибка;
- число параллельных запусков ограничено политикой v1.

### [v1] [p0] T6: сеть и секреты

Проверки:
- запросы идут только на allowlisted host/base-url;
- TLS-проверка включена;
- секреты читаются из OS secret store;
- нет fallback в plaintext-конфиг;
- секреты не попадают в логи и сообщения.

### [v1] [p0] T7: аудит и контракт ответа

Проверки:
- лог содержит только безопасные поля;
- `file-id` в журнале записывается как HMAC-идентификатор;
- retention политики аудита применяется;
- адаптер корректно обрабатывает варианты ответа `file_anonymization`.

### [v2] [p1] T8: операционные усиления

Проверки:
- задокументированы и применяются процедуры rotation/revocation;
- при сценарии компрометации выполняется регламент реакции;
- MCP-слой не ослабляет проверки безопасности v1.
