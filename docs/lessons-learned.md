# lessons-learned

Накопительный документ по итогам закрытия версий.

## Формат записи

- Версия
- Что сработало
- Что не сработало
- Что меняем дальше

## Записи

### v1

- Что сработало:
  - итерационный цикл `openspec -> tdd -> verification` позволил закрыть критичные security-требования (`OS secret store`, path hardening, anti-DoS лимиты, audit HMAC+retention) без деградации UX;
  - обязательная трассировка `requirement -> task -> test -> runtime evidence` снизила риск расхождения между планом и реализацией.
- Что не сработало:
  - на раннем этапе `v1-i1` было упущение по security-декомпозиции (OS secret store попал в plan, но не попал в runtime-задачи), что привело к доработке после ревью;
  - формальное закрытие версии и статусные документы (`roadmap`, `openspec`) были обновлены позже фактической готовности кода.
- Что меняем дальше:
  - для всех новых итераций сохраняем обязательный security-DoD и release-checklist перед закрытием;
  - фиксируем «версия закрыта» только после одновременного обновления `action-log`, `roadmap`, `lessons-learned` и архивирования feature-пакетов.
