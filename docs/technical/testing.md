# testing

## Цель

Подтверждать security и корректность поведения через автоматические проверки, а не вручную.

## Слои тестирования

1. Unit:
  - `resolver`
  - `pathguard`
  - `output naming`
  - `error mapping`
2. Integration:
  - API adapter контракта `file_anonymization`
  - взаимодействие с SQLite-каталогом
3. E2E:
  - пользовательский поток `scan -> list -> run`
  - негативные security-кейсы

## Release gate

Для `v1` обязательны все `p0` сценарии с меткой `[v1]` и `[v1+v2]` из `../test-scenarios.md`.

## Минимальный отчет перед релизом

- Версия CLI.
- Статус `p0` тестов.
- Перечень известных ограничений.
- Ссылка на журналы/артефакты прогона.
