# architecture

## Цель

Базовая архитектура `v1` — модульный монолит CLI на Go с единым trusted-core.

Главные свойства:
- raw-файлы доступны только trusted sidecar CLI;
- отправка в API выполняется только по явной команде `run`;
- анонимизированные файлы пишутся в workspace;
- модель безопасности `v1` сохраняется без ослабления в `v2`.

## Контекстная схема

1. Пользователь запускает `anonym`.
2. CLI читает конфиг и секреты из OS secret store.
3. CLI работает с `raw_path` вне workspace и ведет локальный каталог.
4. При `run` CLI отправляет файл в корпоративный API.
5. Результат сохраняется в `output_path` с безопасным именем.
6. Аудит пишется без PII и без секретов.

## Технологический стек

- Язык: `Go 1.24+`.
- CLI: `cobra`.
- Конфиг: `viper` + собственная схема валидации.
- Локальное состояние: `SQLite` (`modernc.org/sqlite`, без cgo).
- Секреты: `keyring` (Windows Credential Manager / macOS Keychain / Linux Secret Service).
- Логи: `zap`.
- Релизы: `goreleaser`.

## Архитектурные принципы

- Ядро не знает про MCP и UI-обертки.
- Все внешние интеграции проходят через адаптеры.
- Безопасность проверяется до любой операции записи/сети.
- Контракты ошибок стабильны и пригодны для автоматизации.
