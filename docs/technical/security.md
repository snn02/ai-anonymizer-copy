# security

## Security-модель `v1`

- `raw_path` расположен вне workspace IDE.
- Только trusted sidecar CLI имеет доступ к raw и сети API.
- IDE не читает raw-файлы напрямую.
- Отправка только по явной команде пользователя.

## Временный режим `mvp`

Проблема:
- в изолированных средах AI IDE runtime может не иметь доступа к OS secret store хоста.

Временная модель для `mvp`:
1. Режим включается явно и не является дефолтом.
2. API auth-токен и audit HMAC secret передаются через env/config внутри изолированного окружения.
3. Режим допускается в production API-контуре при явном включении и предупреждении.
4. Режим сопровождается компенсирующими ограничениями:
  - ограниченный partner/scope;
  - rate-limit на стороне API;
  - обязательный регламент revoke/rotation;
  - предупреждение пользователю при каждом запуске insecure-режима.

Ограничение:
- `mvp` не отменяет и не ослабляет базовую security-модель `prod`; это временное исключение для MVP в изолированных средах.

## Обязательные проверки

1. Boundary:
  - `raw_path` вне workspace;
  - отказ при небезопасной конфигурации.
2. Path hardening:
  - canonical path;
  - anti-traversal;
  - anti-symlink/reparse;
  - anti-ADS;
  - только обычные файлы.
3. Сеть:
  - только HTTPS;
  - TLS verification обязательно;
  - allowlist host/base URL.
4. Секреты:
  - в `prod`: только OS secret store;
  - в `mvp`: секреты допускаются из env/config.
5. Аудит:
  - без PII;
  - без секретов;
  - file-id в HMAC-виде.

## Лимиты устойчивости

- `max_file_size`
- `max_pages` (для поддерживаемых форматов)
- `request_timeout`
- `max_parallel_runs=1` по умолчанию

## Политика логирования

- Структурные события с техническими кодами.
- Ошибки пригодны для диагностики, но без чувствительных данных.
