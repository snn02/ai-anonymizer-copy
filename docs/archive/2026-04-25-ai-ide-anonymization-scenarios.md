# Пользовательские сценарии и UX-команды: анонимизация файлов

## 1) Назначение

Документ описывает, как пользователь работает с CLI `anonym` в ежедневном режиме без необходимости каждый раз указывать полный путь к файлу.

## 2) Базовые понятия

- `raw_path`: абсолютный путь к папке с исходными файлами вне workspace IDE.
- `output_path`: папка внутри workspace, куда сохраняются анонимизированные файлы.
- `id файла`: стабильный идентификатор записи из `anonym list`.

## 3) Основные сценарии

### Сценарий A: первичная настройка workspace

1. Администратор или пользователь задаёт `raw_path` и `output_path`.
2. Проверяет конфигурацию командой `anonym doctor`.

Ожидаемый результат:
- CLI подтверждает корректные пути, доступ к API и наличие секретов.

### Сценарий B: ежедневный поток (рекомендуемый)

1. Пользователь запускает `anonym scan`.
2. Пользователь запускает `anonym list`.
3. Пользователь выбирает `id` и запускает `anonym run <id>`.

Ожидаемый результат:
- В `output_path` появляется новый файл с суффиксом `.anonymized`.
- Исходный файл в `raw_path` не удаляется и не перемещается.

### Сценарий C: запуск по точному имени или относительному пути

1. Пользователь запускает `anonym run <relative_path>`.
2. CLI ищет файл только внутри `raw_path`.

Ожидаемый результат:
- При точном совпадении начинается обработка.
- При отсутствии файла CLI возвращает понятную ошибку и подсказки.

### Сценарий D: запуск по примерному имени

1. Пользователь запускает команду вида `anonym run invoice april`.
2. CLI выполняет поиск совпадений только в пределах `raw_path`.

Ожидаемое поведение:
- Если совпадение одно: обработка запускается.
- Если совпадений несколько: обработка не запускается, CLI показывает список кандидатов с `id`.
- Если совпадений нет: CLI предлагает похожие варианты.

## 4) UX-команды v1

- `anonym scan`
  - Обнаружить новые и изменённые файлы в `raw_path`.

- `anonym list`
  - Показать найденные файлы и их статусы.

- `anonym run <id|path> [--fields <value>] [--tags <csv>] [--tags-numeration 0|1]`
  - Запустить анонимизацию выбранного файла.

- `anonym doctor`
  - Проверка конфигурации, секретов, доступности API и поддерживаемых форматов.

## 5) Правила безопасности при выборе файла

1. Запрещён выход за пределы `raw_path`.
2. Запрещены path traversal-паттерны (`..`).
3. Обрабатываются только файлы, а не директории.
4. Неподдерживаемые расширения блокируются с понятной причиной.

## 6) Сообщения пользователю

Минимальные требования к сообщениям CLI:
- чёткий итог операции (`успех/ошибка`),
- идентификатор файла (`id`) и путь результата,
- код и причина ошибки без утечки PII,
- понятная следующая команда для пользователя.

## 7) Примеры

- По рекомендованному потоку:
  - `anonym scan`
  - `anonym list`
  - `anonym run 42`

- По точному имени:
  - `anonym run incoming/2026-04/invoice-124.pdf`

- По примерному имени:
  - `anonym run invoice april`
