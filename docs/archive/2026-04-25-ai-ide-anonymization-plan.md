# План: безопасная анонимизация файлов для ИИ-IDE (v1 sidecar CLI, v2 MCP)

## 1) Краткое резюме

Цель: организовать поток, в котором ИИ-IDE (Codex/OpenCode/Claude) работает только с обезличенными файлами.

Зафиксированные решения:
- Пилот: сначала в Codex.
- В `v1`: доверенный `sidecar CLI` с командами `anonym ...`.
- В `v2`: MCP-обёртка над тем же CLI-ядром.
- `raw`-файлы лежат **вне workspace IDE**.
- В проект попадают только анонимизированные файлы.
- В `v1` watcher только помечает новые файлы; отправка в сервис выполняется явной командой.
- Область `v1`: только анонимизация (без деанонимизации).
- Пользовательские сценарии и UX-команды: [2026-04-25-ai-ide-anonymization-scenarios.md](./2026-04-25-ai-ide-anonymization-scenarios.md).

## 2) Архитектура v1 (sidecar CLI)

### 2.1 Компоненты

1. `anonym` (локальный sidecar CLI)
- Единая доверенная точка доступа к корпоративному API анонимизации.
- ИИ-агент в IDE вызывает только CLI-команды и не читает исходные raw-файлы.

2. Корпоративный сервис анонимизации
- Используемые ручки:
  - `POST /v1/tasks/file_anonymization`
  - `GET /v1/tasks/anonymization_file_types`
  - `GET /v1/tasks/anonymization_fields`

3. Локальное состояние sidecar
- Индекс обнаруженных файлов и статусов (`new/scanned/sent/succeeded/failed`).
- Метаданные обработки и причины ошибок без PII-контента.

### 2.2 Поток данных

1. Watcher/scan обнаруживает новые raw-файлы во внешней защищённой папке.
2. Пользователь в чате просит показать новые файлы: `anonym list`.
3. Пользователь запускает обработку файла: `anonym run <id|path>`.
4. CLI читает файл локально и отправляет его в корпоративный API.
5. Анонимизированный результат сохраняется в рабочую папку проекта (например, `./sanitized`) как новый файл с суффиксом.
6. Исходный raw-файл автоматически не удаляется и не переносится.

## 3) Контракт и поведение CLI

### 3.0 Конфигурация workspace

- `raw_path`: абсолютный путь к папке с исходными файлами вне workspace IDE.
- `output_path`: путь к папке внутри workspace, куда пишутся анонимизированные файлы.
- В `v1` команды по умолчанию работают в рамках `raw_path` и `output_path`; полный путь к файлу каждый раз не обязателен.

### 3.1 Команды v1

- `anonym scan`
  - Обнаружить новые/изменённые raw-файлы.
  - Ничего не отправляет в API.

- `anonym list`
  - Показать очередь и статусы файлов, доступных для запуска.

- `anonym run <id|path> [--fields <value>] [--tags <csv>] [--tags-numeration 0|1]`
  - Отправить выбранный файл на анонимизацию.
  - По умолчанию использует профиль из конфигурации.
  - Переопределение параметров разрешено для частных кейсов.

- `anonym doctor`
  - Проверка доступности API, секретов, partner-id и поддерживаемых типов.

### 3.2 Параметры API (из текущей OpenAPI-спеки)

`POST /v1/tasks/file_anonymization`:
- Заголовки:
  - `Authorization` (API key)
  - `fields` (обязательный)
  - `partner-id` (обязательный UUID)
  - `tags-numeration` (опционально, 0/1)
- Тело `multipart/form-data`:
  - `file` (обязательный binary)
  - `tags` (опционально)
  - `partner_replacements` (опционально, JSON-строка)

### 3.3 Политика записи результата

- Результат пишется только в рабочую папку проекта.
- Имя файла: новый файл с суффиксом (например, `report.anonymized.pdf`).
- Перезапись существующего результата в `v1` запрещена по умолчанию.

## 4) Безопасность и комплаенс

### 4.1 Граница доступа (ключевая гарантия)

Чтобы обеспечить требование «сам исходный файл ИИ не читает и никуда не отправляет»:
- Raw-папка физически находится вне workspace IDE.
- ИИ-IDE не должна иметь чтение raw-каталога.
- Только sidecar CLI имеет доступ к raw и сеть к корпоративному API.

### 4.2 Секреты

- `Authorization` и `partner-id` хранятся в `OS secret store`.
- Секреты не хранятся в файлах проекта и не печатаются в логи.

### 4.3 Логирование и аудит

Логируем:
- timestamp,
- file-id/hash,
- endpoint,
- result status,
- request_id,
- error_code.

Не логируем:
- содержимое raw-файла,
- PII-фрагменты,
- секреты и ключи.

### 4.4 Ошибки

- Политика `v1`: fail-fast и понятное сообщение пользователю.
- Авто-ретраи не делаем; повторный запуск — явной командой пользователя.

## 5) План внедрения по этапам

### Этап 1 (v1, сначала Codex)

1. Реализовать sidecar CLI (`scan/list/run/doctor`).
2. Подключить к API и preflight-валидации типов/полей.
3. Внедрить хранение секретов в OS secret store.
4. Добавить журналы аудита без PII.
5. Провести e2e-пилот в Codex.

### Этап 2 (v2)

1. Добавить MCP-обёртку поверх существующего CLI.
2. Сохранить CLI как trusted-core без изменения security-модели.
3. Подключить OpenCode и Claude через MCP tool-интерфейс.

## 6) Критерии приёмки

1. ИИ-IDE не имеет доступа к raw-папке и не читает raw-файлы.
2. Пользователь может обнаружить новые raw-файлы (`anonym list`) и запустить обработку (`anonym run`).
3. Анонимизированный файл создаётся в рабочей папке проекта, исходник не изменяется.
4. Неподдерживаемые форматы и API-ошибки дают понятный статус и диагностическое сообщение.
5. В логах нет PII и секретов.

## 7) Принятые допущения

- Корпоративный API доступен из контура, где запускается sidecar.
- Формат успешного ответа `file_anonymization` может быть разным по типам файлов; в `v1` парсинг делается через адаптер результата и проверяется интеграционными тестами.
- Деанонимизация не входит в текущую область проекта.
